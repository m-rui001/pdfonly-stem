# OpenMS：面向质谱数据分析的灵活开源软件平台

*OpenMS: a flexible open-source software platform for mass spectrometry data analysis* · Nature Methods, 2016, 13(9): 741–748 · doi: 10.1038/nmeth.3959

OpenMS 2.0 是一个开源、跨平台、面向高通量质谱数据的软件平台，目标是让质谱蛋白质组学与代谢组学分析既灵活又可复现。作者指出，高分辨质谱已成为生命科学的重要工具，但数据量与复杂度快速增长，使透明、准确、可复现的分析变得困难；而技术快速演化、软件生态高度异质、分析流程需针对具体样本与实验条件定制，进一步加剧了这一困难。质谱应用于代谢组学、蛋白质组学、相互作用组学和脂质组学等领域，各领域的数据采集与分析方式差异显著；分离方法（气相色谱、液相色谱）、碎裂方法（CID、ECD、ETD、HCD 等）与采集策略（数据依赖、数据非依赖或靶向）可组合出极多方案；定量又可采用无标记、同量异位或同位素标记策略（如蛋白质组学中的 ICAT、SILAC、iTRAQ、TMT）。分析步骤还可能包括数据库搜索、谱库搜索或靶向分析。因此通常需要复杂、多步且相互依赖的分析流程，例如发现型蛋白质组学流程包含文件转换、质心化、数据库搜索、特征检测、保留时间对齐、跨运行特征连接、蛋白推断以及各步骤的统计错误控制。

作者将由此产生的计算挑战归纳为三点：其一，领域内使用多种数据格式描述原始数据及各分析步骤（鉴定、定量、保留时间对齐等）的输出；其二，已有大量软件包各自完成复杂流程中的一步或几步，却常依赖自定义的输入、输出与预处理代码（如质心化、平滑或同位素去卷积），重复实现既耗时又易错，并可能造成不同工具间结果差异；其三，单个工具通常难以集成到单一计算平台上的更大流程中。既往工作推动了标准化数据交换格式的发展，这些格式已被多个软件项目采用，使不同来源的工具得以整合、多厂商质谱数据更易分析、已发表结果更易获取，并让公开数据无需专有软件即可转换与检查，从而成为开放科学的基石。但复现其他实验室的结果、把单个工具整合进流程仍然困难，新实验往往需要从头开始；维护和记录计算流程通常要求较高的计算知识，而透明可复现的分析需要完整记录包括所有工具参数在内的整个流程，使其成为可数字化、可复现的“计算标准操作程序（computational SOP）”，从而减少错误并使复杂分析更易被新用户掌握。

OpenMS 通过提供同时适合终端用户与软件开发者的灵活专业软件环境来应对这些挑战，并给出三个层次的访问方式：(i) 面向标准任务的预组装流程，作为最佳实践“配方”，可在强大的图形分析工作台或商业流程工具（如 Proteome Discoverer、Compound Discoverer 或 BaseSpace）中实现广泛使用的分析类型；(ii) 超过 180 个独立工具，可单独使用，也可与其他兼容的开源工具组合；(iii) 强大的算法核心库与 Python 脚本接口，供软件开发者实现新算法。自 2008 年最初的 C++ 软件库发布以来，OpenMS 项目已加入面向高分辨鸟枪法蛋白质组学、靶向蛋白质组学、同位素标记、交联、宏蛋白质组学、蛋白质基因组学和代谢组学的算法。OpenMS 2.0 扩展了功能，提供大量面向用户的预构建工具与流程以支持可复现的质谱数据分析，并已与图形化流程系统（如 KNIME、Galaxy、Proteome Discoverer 或 Compound Discoverer）完全整合，使其更易被实验生命科学家使用，在生物信息学家手中也更强大。

## 面向生物信息学家的 OpenMS

OpenMS 以 C++ 编写，在 Windows（MSVS）、Linux（Clang 和 GCC）与 OS X（Clang）上提供原生编译器支持，并提供到 Python 脚本语言的接口以直接访问核心数据结构与算法。它采用现代软件工程概念，强调模块化、可复用性，并通过持续集成进行广泛测试。宽松的 BSD 许可证鼓励在商业与学术环境中使用，促进合作与联合研究。其多级架构允许在不同层次上交互与扩展：用户生成的流程由各个可执行工具（TOPP 工具）组成，而这些工具本身使用核心 C++ 库中的算法；这一设计使库中的通用算法能方便地组合成强大、高性能的分析工具与完整分析流程。每一层只依赖前一层的功能，并通过组合强大的独立组件提供更高的效用。

最底层是数据与信号处理层，建立在用于数值计算、XML 解析、序列分析和统计的开源库之上，提供对质谱数据格式与常见预处理算法的统一访问入口。OpenMS 实现了 30 多种文件格式，包括 HUPO-PSI 当前及即将推出的开放标准，如 mzML、TraML、mzIdentML、mzQuantML、mzTab 和 qcML。此外，OpenMS 还包含与生物分子性质相关的标准算法（如质量计算、同位素组成、蛋白消化等）以及信号处理算法（如平滑、基线校正、去同位素和峰提取）。这使开发者能以稳健的库为基础开发新算法，而不必重新实现基础功能；更重要的是，经过验证的软件库集中维护并由多位开发者测试，可减少错误，使用户在多个软件工具与计算平台上获得行为一致、可预测的更可靠代码。OpenMS 还实现了最常见的定量蛋白质组学与代谢组学任务，包括定量、鉴定和可视化，以及同位素去卷积、色谱峰提取、保留时间对齐或跨多次运行的特征连接等算法。开发者可直接将新算法与这些参考实现进行基准比较，从而实现与既有算法的有意义对比；若干用于 OpenMS 算法开发的“金标准”数据集可免费获取，也支持这种比较。借助底层数据访问与信号处理例程，新算法可通过增强某个工具或简单替换现有步骤而方便地加入已有流程，对使用 OpenMS 的生命科学实验室而言，这意味着能以对现有流程最小的干扰快速获得改进算法。

核心 OpenMS 库已被用于实现广泛的面向用户的工具与流程。这些所谓 TOPP 工具是使用 TOPPBase 基类实现的独立可执行程序，通常提供对特定功能的访问（SWATH 分析、RNA 交联分析、SILAC 定量等）。TOPP 工具要么使用 OpenMS 中可用的一组算法提供功能，要么通过所谓适配器工具促进外部工具的使用。大多数 TOPP 工具还自动集成到查看器 TOPPView 中，非开发者可从图形用户界面直接将其应用于数据。此外，各个 TOPP 工具自动作为节点出现在 KNIME 或 Galaxy 等工作流管理器中，使用户能将其整合进自己的流程，并从新算法方法的发展中获益。

为快速进行软件原型开发，OpenMS 提供在 Python 编程语言中直接访问所有数据结构与算法的能力。pyOpenMS 接口即使对仅具备基本编程技能的用户也提供极大的灵活性：他们可直接与 OpenMS 核心库交互，并使用与 C++ 中相同（且高效）的数据结构在 Python 中实现算法。这对不熟悉底层语言但仍希望使用 OpenMS 算法的研究者尤其有吸引力。Python 也非常适合快速软件原型开发，使开发者能快速测试新算法想法，待完善后再加入 C++ 核心；OpenMS 架构使算法易于移植回 C++。Python 框架还被用于构建使用 OpenMS 进行繁重数据处理的独立应用（例如 eMZed 或 TAPIR）。通过在 Python 中直接编写代码，研究者可受益于质谱之外大量可用的生物信息学包与算法；这些代码通常可通过单个包访问并导入现有代码，功能范围从数值计算、信号处理到基于测序的分析和结构分析。将完整 OpenMS 功能作为包加入 Python 后，社区能够混合搭配这些不同软件包。作者提到，他们最近将 pyOpenMS 与 PyMOL 一起使用，从一次质谱实验中提取已鉴定肽段，并用不到 50 行 Python 代码将这些肽段绘制到相应蛋白的 3D 结构上。

OpenMS 的开发是团队协作，维护任务分配给所有开发者；国际团队内的在线讨论、强制代码审查、高测试覆盖率和持续集成确保高代码质量并促进合作。多平台夜间构建与频繁发布使新代码能快速分发给用户。OpenMS 可执行程序与工作流引擎的紧密集成意味着用户可直接在其熟悉的环境中以节点形式获得新工具，开发者则受益于集中式基础设施，为测试和开发跨多个平台生成这些节点。作者指出，OpenMS 是应对基于质谱的蛋白质组学计算挑战的多个软件方案之一，各方案在蛋白推断、肽数据库搜索或文件转换等不同领域有所贡献；一些专有软件包为专门用例提供解决方案，但其封闭性使其难以适应新需求并整合进更复杂的流程；相比之下，OpenMS 整合了多个开源项目，并邀请用户与开发者以多种方式贡献。

代码复用与可扩展性是 OpenMS 这类软件框架的主要优势。编写稳健、正确、高效的高质量代码耗时，且常需多年真实数据测试才能发现可能的边界情况；OpenMS 在该领域有长期积累，并有大量经验丰富的开发者社区维护核心库。在 OpenMS 中，代码组织为各个类与模块，每个实现特定概念、文件格式或算法，每个模块可独立使用并遵循最小惊讶原则。这使开发者可在其 C++ 和 Python 代码中纳入 OpenMS 模块，而不必自行编写，从而节省时间并避免可能错误。OpenMS 中进行的广泛测试确保代码可在所有支持平台上运行，并在未来版本中行为一致。

## 面向实验人员的 OpenMS

OpenMS 提供 180 多种不同工具，用于执行从文件转换、数据提取到定量、保留时间对齐、数据库搜索等不同复杂度的任务。每个工具都提供标准化接口和通用文件格式来读写输入输出。工具可从命令行单独使用，也可在由预配置工具按确定顺序组成的分析流程中调用。通过以不同组合和不同参数组合不同工具，OpenMS 可覆盖广泛的可能实验应用。理想情况下，这些流程直接从初始原始数据转换开始，并生成完整的数据集分析结果，可直接存入公共仓库（多数出版商要求如此）。虽然基于 OpenMS 的预配置流程可用于许多标准分析，但简单创建新流程是 OpenMS 的一个优势。构建这些流程不需要任何编程专业知识，可通过集成工作流环境（如 KNIME、Galaxy 等）中的图形用户界面完成；这些工作流管理器甚至能让缺乏经验的用户在几分钟内修改和扩展现有数据分析流程。用户创建的流程可通过 OpenMS 网站或公共流程仓库（如 http://www.myexperiment.org）共享，使其他实验室只需下载单个文件并在工作流编辑器中打开即可复现流程。流程文件指定所有输入文件、要执行的工具及每个工具的参数，从而使分析的每个细节完全透明和可复现。这些流程也可在没有图形用户界面的情况下在更大数据集上执行。整合外部软件（如用于文件转换的 ProteoWizard，用于数据库搜索的 OMSSA、X! Tandem、MSGF+ 和 Percolator，或用于蛋白推断的 Fido）使研究者能在单一流程环境中完成所有处理。

OpenMS 查看器应用 TOPPView 提供质谱数据的高级可视化，能显示数据的一维表示（谱图、色谱图），也能以二维和三维表示渲染数据（m/z 与 RT 维度上的强度）。许多图形程序常见的基于图层的系统允许将不同数据集作为图层叠加，例如比较多个数据集，或比较原始数据与计算得到的定量结果。用户可多种方式与数据交互，放大到谱图级别探索原始数据，或提取离子色谱图。与众多 OpenMS 可执行程序的紧密集成使用户能直接将 OpenMS 算法应用于数据并观察其效果；工具在后台应用，用户可继续工作。对可见数据子集的直接反馈使用户能微调参数并直观理解数据处理效果。部分 OpenMS 工具（如蛋白质组学无标记定量、RNA-蛋白交联、非靶向代谢物定量）也已整合进商业工作流引擎和分析套件（Proteome Discoverer 和 Compound Discoverer），将 OpenMS 工具带入许多用户已熟悉的平台，并实现与厂商构建的质谱原始数据可视化的无缝整合。

在可复现研究方面，大规模组学分析的复杂性意味着只有提供所有工具及其设置的完整详尽记录，才能复现计算方案。OpenMS 通过允许用户将流程存储在易于传输的流程文件中来支持可复现研究，这些文件自动包含所有工具、其版本号和所用参数的完整记录。这意味着用户可获得已发表手稿中应用的精确流程，详细分析并在自己的数据上运行。OpenMS 与执行数据转换、数据库搜索、错误率估计和蛋白推断的外部工具的全面整合，确保所有步骤参数都被记录，分析描述中没有“缺失部分”。结果随后可在 TOPPView 中可视化。一旦实验室建立了新的分析流程，研究者可将流程文件上传到 OpenMS 网站或其他仓库，从而记录其工作并使其他研究者能复现其分析。

作者列举了研究者使用 OpenMS 构建复杂分析工具的一些近期例子，包括对无标记定量流程的改进、代谢组学流程的开发、RNA 交联流程的整合，以及使用 SWATH-MS 的靶向数据分析流程的加入；此外，OpenMS 还被扩展以包含概率打分引擎、SILAC 分析、同量异位定量、随机访问 XML 文件解析和质谱模拟框架。这些例子说明核心框架的灵活性与通用性。随后三个案例研究突出了 OpenMS 核心库的可扩展性、使用灵敏的 OpenMS 特征检测算法进行定量的能力，以及将 OpenMS 流程应用于大型公共数据集。

在 SWATH 数据分析案例中，人血浆蛋白丰度的变异程度及其潜在原因在很大程度上未知；大规模人血浆蛋白质组学测量可提供关于蛋白丰度个体间与个体内变异的深入信息，并可用于研究衰老过程中的纵向趋势。在一项近期研究中，Liu 等人使用 SWATH-MS 在一项纵向研究中采集了来自同卵和异卵双胞胎的 200 多份血浆样本。为获得最大灵敏度，作者选择了此前使用 OpenMS 软件库开发的 SWATH-MS 数据靶向分析策略。具体而言，OpenSWATH 分析模块是使用现有的文件解析、保留时间对齐和信号处理算法与数据结构开发的；开发者因此可依赖经过充分测试的 OpenMS 框架完成核心任务，并将精力集中于新算法开发。此外，OpenMS 的可扩展性意味着靶向数据分析特有的新算法（如靶向提取、色谱峰检测和打分）可无缝整合进现有 C++ 库。OpenSWATH 的高灵敏度使 Liu 等人能够定量 300 多种血浆蛋白，并将每个蛋白观察到的方差分解为可遗传、环境（共同与个体）和纵向成分。有趣的是，作者发现血浆蛋白变异的可遗传成分范围从超过 60% 到几乎为零；此外，将蛋白质组学数据与个体基因组整合，鉴定出 13 个 cis-pQTL，其中两个与人类疾病相关。

在降解组学案例中，人类蛋白酶是一大类与多种疾病相关的多样蛋白，但其研究在分析上具有挑战性。在一项近期研究中，Lai 等人使用定量蛋白质组学和稳定同位素标记，结合生化富集方法，从福尔马林固定石蜡包埋（FFPE）样本（代表临床档案中存储的绝大多数样本）中鉴定蛋白酶产生的蛋白新末端。OpenMS 使多种常见 N 端修饰在不同同位素标记状态下的平行、无偏分析成为可能，也实现了稳定同位素标记肽段的准确定量相对定量。这包括处理所谓“敲除”情形，即某肽段仅出现在一种同位素状态而在相应第二同位素通道中缺失；这种情况通常因色谱背景信号而易于产生扭曲定量，而该问题可通过 OpenMS 中准确的肽段特征检测解决。该流程在 FFPE 样本中表征了数千个蛋白 N 端，并鉴定出 23 个溶酶体蛋白酶 cathepsin L 的新潜在底物。

在蛋白质基因组学案例中，Wright 等人使用公开可用的质谱数据，利用蛋白质组学数据改进人类基因组中蛋白编码区域的注释。该研究目的是鉴定新的蛋白编码基因、改进现有基因模型的证据，并开发严格的数据分析流程。Wright 等人使用 OpenMS 实现了完整的蛋白质基因组学分析流程，涵盖使用多个搜索引擎的数据库搜索、搜索结果的重打分与合并、在 PSM、肽段和蛋白水平上按多种标准过滤，以及数据导出，全部在 OpenMS 内完成。使用 OpenMS 处理来自不同公开数据集的超过 5500 万张串联质谱图，使他们在 GENCODE 人类参考基因组中发现 40 多个新的蛋白编码基因注释。除鉴定新基因外，蛋白质基因组学分析中获得的关于已知蛋白的信息也可加以利用，例如阐明组织特异性蛋白表达水平。

## 结论与未来发展方向

OpenMS 项目是一个由多个主要实验室支持的社区驱动项目。在过去十年中，OpenMS 建立了庞大的用户与开发者社区；高代码质量和项目的长期维护使其成为可持续软件开发的良好方案。自最初发表以来，在主要会议上举办了培训课程，并举行了八次以上专门用户会议，以教育用户并向领域从业者传播既有流程的知识；这些会议为用户和开发者提供见面交流的机会，同时描述每年纳入 OpenMS 项目的最新算法与进展。OpenMS 项目不仅直接贡献者活跃，其他一些开源工具如 MSStats、aLFQ 和 Skyline 也已开始将其工具与 OpenMS 整合。

作者也承认，虽然 OpenMS 为专家用户和开发者提供极大灵活性，但其复杂性可能对新手用户构成挑战；OpenMS 团队正通过广泛培训活动和大力简化接口来应对。OpenMS 还必须适应不断变化、日益异构和分布式的计算格局，因此面向云计算的工作流驱动解决方案（包括基于 Docker 的虚拟化）是当前发展重点；同时这些努力不应使终端用户的分析复杂化。OpenMS 团队因此也在增加预构建流程的数量，并为各种用例和仪器类型提供详细说明。通过建立用户社区，使用流程文件共享流程与参数设置，最佳实践可从实验室传到实验室，并与原始数据一起存储，使数据分析可复现。OpenMS 团队计划实现更多基于质谱的流程（如蛋白-蛋白交联、脂质组学、小分子），以满足不断增长的用户群需求。当前与工作流管理器、厂商软件和脚本语言的整合已为非专家用户提供多种访问 OpenMS 算法的选择，团队还计划与仪器厂商及其他开源软件开发者建立进一步合作，支持计算质谱中新兴的流程并提供额外用户界面。最后，OpenMS 社区将继续推动蛋白质组学领域的开源软件与开放标准。

OpenMS 是开源软件，在 BSD 三条款许可证下分发。探索 OpenMS 最便捷的方式是通过 KNIME 分析平台；下载说明和示例可在 OpenMS 网站（http://www.openms.org/getting started）找到。所有主要平台的二进制安装程序可从项目网站（http://www.openms.org/downloads）获取。项目源代码完整托管在 GitHub（https://github.com/OpenMS/OpenMS）。
