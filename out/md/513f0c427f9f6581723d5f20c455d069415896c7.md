# FEniCS项目1.5版

*原题：The FEniCS Project Version 1.5*


Martin S. Alnaes, Jan Blechta, Johan Hake, August Johansson, Benjamin Kehlet, Anders Logg, Chris Richardson, Johannes Ring, Marie E. Rognes, Garth N. Wells；2015；DOI: https://doi.org/10.11588/ans.2015.100.20553

本文是 FEniCS 1.5 版本的发布说明与可引用参考。FEniCS 是一个面向自动化科学计算的协作项目，重点是用有限元方法求解微分方程，由一组可互操作的软件组件构成，包括 DOLFIN、FFC、FIAT、Instant、mshr 和 UFL；此外还包括代码生成接口组件 UFC，现已在技术上属于 FFC。除 mshr 因上游依赖采用 GNU GPL 外，其余组件均采用 GNU LGPL。各组件以相同的主次版本号同时发布，未改动的包版本号也会递增以避免版本号分叉。FEniCS 1.5 于 2015 年 1 月 12 日发布，可从 http://fenicsproject.org 下载。

## 并行计算、网格细化与网格生成

DOLFIN 的并行计算性能继续增强。1.5 版的重要改进包括：改用局部（按进程）自由度编号；通过完整支持 64 位索引，全面支持（包括从 Python）超过 $2^{32}$ 个自由度的问题；自由度映射构造的性能扩展和内存使用显著改善；新的并行网格细化策略；支持并行重叠网格的“ghost”层；支持内部面片积分，从而使间断 Galerkin 方法可并行；改进使用 HDF5 的并行 IO。DOLFIN 已在 Cray XC30 的 24576 个核上求解超过 120 亿自由度的 Poisson 方程 [Richardson and Wells, 2015]。为减少大型机器上即时编译对文件系统的负载，也做了改进；但并行计算机上导入 Python 模块这一已知问题仍需进一步解决。基于 OFED（InfiniBand）集群在 fork 期间的内存损坏问题已被定位，建议 OFED 机器用户阅读 Instant README 并导出 INSTANT_SYSTEM_CALL_METHOD 环境变量。

新的网格细化算法采用 Plaza and Carey [2000] 的工作，使用边二分法细分 Mesh 中被标记的三角形：二维时是单元本身，三维时是四面体的面片。细分选择旨在最大化新三角剖分的内部角，从而在多次细化后保持网格质量（Figure 1）。被标记细化的边在并行进程间传播，而细化操作是局部的，因此扩展性良好。

除 UnitSquareMesh 和 UnitCubeMesh 等简单网格外，FEniCS 的网格生成功能已移至新组件 mshr。动机有二：简化依赖列表并减少构建 DOLFIN 的资源（CPU 时间和内存），办法是把 CGAL 依赖移到 mshr；以及简化向新网格组件添加新功能。目前 mshr 可用 CGAL 和 Tetgen 作为网格生成后端。与 DOLFIN 旧网格接口类似，新 mshr 接口允许从构造实体几何（CSG）描述简单生成网格，示例代码定义了 box、sphere、cylinder，并通过 `geometry = box + cylinder - sphere` 和 `mesh = generate_mesh(geometry, 16)` 生成网格（Figure 2）。通过简单 CSG 基元和布尔运算（与、或、取反）的组合，可以创建从简单区域（如典型 L 形区域）到相对复杂几何的网格；Figure 3 展示了用 mshr 生成的一对网格。

## 多网格有限元方法、点积分与符号表示重设计

多网格有限元方法（CutFEM）是在两个或多个可能不匹配的网格上提出的有限元方法。其表述涉及在相交网格上的正则函数空间组成的函数空间上构造变分问题；网格间连续性用 Nitsche 方法施加，稳定性通过向变分问题添加合适的稳定项（ghost penalties）保证。FEniCS 1.5 增加了对多网格方法表述的支持，包括自动高效计算网格-网格相交、切割单元和界面的求积规则，以及表达多网格/CutFEM 表述中通常出现的积分。Figure 4 展示了在两个重叠且相交网格上求解 Stokes 问题的 Taylor-Hood 表述结果：一个嵌入螺旋桨形孔的边界拟合网格与固定背景网格重叠；细节见 Johansson et al. [2015]。目前 FEniCS 的多网格有限元方法接口要求用户用新增的 custom_integral 接口定义积分，该接口可为任意区域（包括切割单元、界面和重叠区域）上表达的积分生成代码。文中给出了 Poisson 方程多网格表述的 UFL 代码，其中定义了 `dc0 = dc(0, metadata={"num_cells": 1})`、`dc1 = dc(1, metadata={"num_cells": 2})`、`dc2 = dc(2, metadata={"num_cells": 2})`，并设置 `dx = dx + dc0`、`di = dc1`、`do = dc2`，参数 `alpha = 4.0`、`beta = 4.0`，双线性形式为 `a = dot(grad(u), grad(v))*dx - dot(avg(grad(u)), jump(v, n))*di - dot(avg(grad(v)), jump(u, n))*di + alpha/h*jump(u)*jump(v)*di + dot(jump(grad(u)), jump(grad(v)))*do`。C++ 侧目前必须显式构造多网格函数空间，示例中创建 `MultiMeshPoisson::FunctionSpace V0(mesh_0)`、`V1(mesh_1)`、`V2(mesh_2)`，再构建 `MultiMeshFunctionSpace V`，设置 `V.parameters("multimesh")["quadrature_order"] = 2`，依次 `V.add(V0)`、`V.add(V1)`、`V.add(V2)`，最后 `V.build()`。未来改进包括在 UFL 中引入特定积分测度，使测度不必用 custom measure 定义，以及在 DOLFIN 中为组装和问题求解提供简化且更高层的接口。

除经典单元积分、外部面片积分和内部面片积分外，FEniCS 1.5 支持指定点积分。点积分表示在每个顶点处求值的被积函数，并在网格所有顶点上求和。从 1.5 版开始，DOLFIN 组装器识别点积分并组装其贡献。需要注意，对每个顶点，被积函数在求值前会被限制到与该顶点关联的任意选择的第一个单元；因此该操作仅对在顶点处连续的函数和被积函数才有一致定义。FEniCS 的 PointIntegralSolvers 是专用求解器，用于求解为网格每个顶点定义的多级积分格式，这类问题通常出现在空间变化的 ODE 系统中，例如电生理学。1.5 版将可用格式扩展到包括 Rush-Larsen [Rush and Larsen, 1978] 和广义 Rush-Larsen [Sundnes et al., 2009] 格式，用于求解非线性 ODE 系统。

UFL 将方程表示为符号表达式树，每个节点表示某个值或数学运算。对于具有大表达式树的非线性方程，符号计算和形式编译器算法的性能与内存开销可能变得显著，尤其在并行运行时，这种开销是 Amdahl 定律下可扩展性的限制因素；当 FEniCS 与 dolfin-adjoint 等大量依赖 UFL 符号算法的高层算法结合时更为重要。为降低开销，符号表达式的核心表示已重新设计（见 ufl.core），随后重写了用于开发额外符号算法的核心框架（见 ufl.corealg）。每个表达式树节点类型现在具有以下属性：`ufl_operands` 是表达式树中子节点的元组，等价于已弃用的 `operands()`；`ufl_shape` 是值形状维度的元组，等价于已弃用的 `shape()`；`ufl_free_indices` 是自由索引整数 id 的元组，替代已弃用的 `free_indices()`；`ufl_free_index_dimensions` 是与 `ufl_free_indices` 中对应自由索引 id 关联的维度元组，替代已弃用的 `free_indices()`。上述已弃用函数仍作为新属性的包装器可用。符号表达式类的类型特征也通过基于属性的高效 API 提供，命名方案为 `ExprType.ufl*_`（见 ufl.core.expr），主要供内部使用，也供基于 FEniCS 符号能力的开发者使用。UFL 核心算法重设计的主要指导原则是用循环替换 Python 中所有昂贵的递归。表达式遍历算法（见模块 ufl.corealg.traversal）均已无递归重新实现，并针对特定迭代场景进一步微调。原先用于 visitor 类算法的 Transformer 基类已弃用，改为避免递归的实现。新函数 `map_expr_dag(function, expression)` 以非递归后序遍历对每个表达式树节点应用给定函数进行变换，函数参数包括节点以及先前变换后的节点操作数；该算法进一步优化以减少函数调用次数，并通过（可选地）以原始表达式节点为键在 hashmap 中缓存中间结果来避免重复表达式树节点。原先 Transformer 类的实现可轻松改写为 MultiFunction 的实现，后者实现相同的动态类型分派机制，并作为函数参数传给 `map_expr_dag`。自动微分（`apply_derivatives`）和限制传播（`apply_restrictions`）等关键算法已在此优化算法框架中重新实现，可作为范例。此外，形式签名现在无需先应用自动微分即可计算，当签名在形式编译器缓存中找到时，显著减少符号开销。这些改进合计将 FEniCS 1.5 中的符号开销降低了 20-60%。例如：Poisson 方程形式的初始即时（JIT）编译（包括 C++ 编译）从 5s 降至 4s；复杂心脏超弹性模型的 JIT 时间从 103s 降至 48s；对后者，后续程序运行现在避免了用于磁盘缓存查找的签名计算中 2s 的延迟。

## 有限元记号、自由度映射与线性代数接口

FEniCS 现在支持《Periodic Table of the Finite Elements》[Arnold and Logg, 2014] 中基于有限元外微积分 [Arnold et al., 2006] 的有限元记号。该记号为 FEniCS 中已有元素引入新别名，并为四边形和六面体上尚未实现的元素引入新占位名。早期 FEniCS 记号（“Lagrange”、“CG”等）仍受支持，但未来版本可能逐步淘汰。Table 1 总结了该记号：其中 n 是有限元区域的拓扑维数（1D、2D、3D），r 是多项式次数，k 是形式次数；k = 0 表示标量，k = 1 表示 1-形式（有向线段），k = 2 表示 2-形式（有向曲面），k = 3 表示 3-形式（有向体积）。表中列出了 $\mathcal{P}_{r}^{-}\Lambda^{k}(\Delta_{n})$、$\mathcal{Q}_{r}^{-}\Lambda^{k}(\Box_{n})$、$\mathcal{P}_{r}\Lambda^{k}(\Delta_{n})$、$\mathcal{S}_{r}\Lambda^{k}(\Box_{n})$ 在 k=0,1,2,3 和 n=1,2,3 下的元素名称，例如 P、DP、RT[E,F]、N1E、N1F、Q、DQ、RTC[E,F]、NCE、NCF、BDM[E,F]、N2E、N2F、S、DPC、BDMC[E,F]、AAE、AAF 等。Figure 5 展示了周期表的微型（但高分辨率）版本，完整版可从 http://femtable.org 下载。示例代码展示了如何在四面体上实例化一对三次 Nedelec 面元素：`element_1 = FiniteElement("N1F", "tetrahedron", 3)` 和 `element_2 = FiniteElement("N2F", "tetrahedron", 3)`。

自由度（DOF）映射构造做了多项性能改进，并改变了 DOF 映射的排序方式。具体包括：DOLFIN 现在使用局部（按进程）自由度编号，减少了自由度映射的内存使用，也允许在线性代数后端接口方面开展一些新开发；自由度映射构造代码已重写，减少了构造时间并显著改善构造的并行扩展性；DOF 映射中的节点块结构（例如每个节点固定数量的 DOF）现在可自动检测，从而提供更好的数据局部性和更快的基于图的 DOF 映射重排序。Figure 6 和 Figure 7 展示了改进 DOF 映射排序后稀疏模式的变化：DOLFIN 1.5.0 产生的稀疏模式更好地聚集在对角线附近；当 DOLFIN 配置 SCOTCH 时，使用 SCOTCH 实现的 Gibbs-Poole-Stockmeyer 重排序。复现 Figure 6 和 Figure 7 及其他网格上稀疏模式的代码见 https://www.repository.cam.ac.uk/handle/1810/252670，网格见 http://fenicsproject.org/download/data.html#meshes。

FEniCS 使用 PETSc 和 SLEPc 库作为后端，提供线性代数、非线性求解器和特征值求解器的并行基础设施。这些包的包装层已改进，特别是：引入了 PETScTAOSolver，即 DOLFIN 对 PETSc TAO 框架的接口，提供非线性优化问题求解器；LinearOperator，即 DOLFIN 对无矩阵算子的接口，现在可解包为相应的 PETSc 或 petsc4py 对象；SLEPcEigenSolver，即 DOLFIN 对特征值求解器的接口，现在可解包为相应的 SLEPc 或 slepc4py 对象。后两者扩展了其他后端包装器（如 PETScMatrix、PETScKrylovSolver 等）已有的功能，允许在 DOLFIN 对后端特性或选项覆盖不够详细时，对求解过程和其他细节进行更精细但仍方便的控制。本版本移除了对 Trilinos Epetra 后端的支持；对更新的 Trilinos Tpetra 后端的支持将在未来版本中加入。

## C++11、Python、安装、演示、接口变更与依赖

FEniCS 团队已开始使用选定的 C++11 特性，从而可以移除对 Boost 共享指针的依赖，并简化部分 C++ 源代码。目前特性集有限，以保持与一些常见编译器兼容；已知 GCC 4.6.3 兼容。对 DOLFIN C++ 接口用户，使用 C++11 可通过关键字 auto、初始化列表和基于范围的循环等写出更简洁的代码。FEniCS 现在要求 Python 2.7，并对 Python 3.x 提供实验性支持。作为支持 Python 3 的一部分，FIAT 不再依赖 Scientific Python；由于 Scientific Python 不支持 Python 3，FIAT 现在依赖 SymPy。

FEniCS 仍作为二进制包包含在标准 Debian 和 Ubuntu 仓库中。希望在这些版本向下游传播前访问最新 FEniCS 版本的用户，可使用个人包档案（PPA）（ppa:fenics-packages/fenics）。Mac OSX 也有二进制包。随着 1.5 版发布，FEniCS 弃用了安装器 Dorsal，改用新工具 fenics-install.sh。该脚本依赖 HashDist（https://hashdist.github.io/）安装 FEniCS 及其依赖。使用该脚本，用户可用一行命令轻松构建 FEniCS：`curl -s http://fenicsproject.org/fenics-install.sh | bash`。需要修改源代码的 FEniCS 开发者被鼓励使用两个相关脚本 fenics-install-all.sh 和 fenics-install-component.sh 作为正常工作流的标准工具；这些脚本是 BitBucket 上 FEniCS Developer Tools 仓库的一部分。此外，FEniCS 现在也可通过社区支持的 Conda recipe 安装（见 https://github.com/Juanlu001/fenics-recipes/releases/tag/v1.5.0），以及通过 FEniCS 网页提供的自定义虚拟化镜像安装。

新增了一些示例程序以演示新的用户级功能：用于三维弹性的平滑聚合代数多重网格，演示多重网格预条件器所需的近零空间的构造和指定，也演示如何为弹性问题构造可扩展求解器；两个新的多网格方法演示：multimesh-poisson 和 multimesh-stokes。

FEniCS 1.5 版做了以下接口变更：类 FacetArea、FacetNormal、CellSize、CellVolume、SpatialCoordinate、Circumradius、MinFacetEdgeLength 和 MaxFacetEdgeLength 现在需要 Mesh 参数而不是 Cell 参数；assemble 函数的签名已简化，不再需要/接受参数 coefficients、cells 和 common_cell；使用 diff 对 Coefficient 或 Function 求表达式微分时，不再需要将函数包装在 variable 构造中；求积次数和规则名可作为关键字指定给形式积分测度，即 `f*dx(degree=3, rule="canonical")`；语法 `Measure.getitem(mesh_function).call(subdomain_id)`，例如 `dx[mesh_function](42)`，已弃用，改用关键字参数，例如 `dx(subdomain_data=mesh_function, subdomain_id=42)`；GenericTensors 不能再重新初始化，因此所有 assemble 函数中的 reset_sparsity 参数已移除；已弃用的 `MPI::process_number` 和 `MPI::num_processes` 已移除，分别改用 `MPI::rank` 和 `MPI::size`；`GenericVector.setitem`，例如 `vec[indices] = values`，现在接受局部索引，可以是 int 列表、int 的 NumPy 数组、int 或完整切片 `:`；values 类型可以是标量、NumPy 数组或 GenericVector（在适用时）；该操作是集合性的，并自动 finalize 向量。

FEniCS（主要是 DOLFIN）依赖若干外部包。必要依赖包括：C++11 编译器（已知 GCC $\geq$ 4.6 和 Clang 3.6 可用），详见 2.11 节；Boost $\geq$ 1.48，提供一些底层数据结构和算法、DOF 重排序和网格着色 [Schling, 2011]；CMake $\geq 2.8$，由 DOLFIN 构建系统使用，也可选用于 Python JIT 链；Eigen $\geq 3.0$，提供自适应求解器使用的数据结构和操作 [Guennebaud et al., 2015]；Python 2.7 或 $\geq 3.2$；six（Python 2 和 3 兼容工具）；FIAT、UFL、FFC 和 Instant 需要，DOLFIN 和 mshr 的 Python 接口可选需要；NumPy，提供 N 维数组数据结构和操作的 Python 包 [van der Walt et al., 2011]；SymPy，Python 符号数学库，由 FIAT 使用 [SymPy Development Team, 2014]。可选依赖包括：OpenMP，支持共享内存系统上的并行计算；MPI，支持分布式内存系统上的并行计算；PETSc $\geq 3.3$，$< 3.6$，作为并行（线性）代数后端，提供处理并行向量、矩阵、Krylov 求解器、稀疏直接求解器、各种预条件器和非线性求解器的数据结构和例程 [Balay et al., 2014b,a, 1997]；petsc4py $\geq 3.3, < 3.6$，提供 PETSc 的 Python 绑定 [Dalcin et al., 2011]；SLEPc $\geq 3.3, < 3.6$，提供并行特征问题求解器 [Hernandez et al., 2005]；slepc4py $\geq 3.5.1, < 3.6$，提供 SLEPc 的 Python 绑定 [Dalcin et al., 2011]；UMFPACK，使用多波前法提供顺序稀疏 LU 分解 [Davis, 2004]；CHOLMOD，使用超节点法提供顺序稀疏 Cholesky 分解 [Chen et al., 2008]；PaStiX $\geq$ 5.2.1，提供并行（分布式和线程化）稀疏 LU 和 Cholesky 分解 [Henon et al., 2002]；Trilinos $\geq 11.0.0$，提供网格划分和着色 [Heroux et al., 2005]；SCOTCH，提供网格划分和 DOF 重排序 [Chevalier and Pellegrini, 2006]；ParMETIS $\geq$ 4.0.2，提供网格划分 [Karypis and Kumar, 1998]；SWIG $\geq$ 2.0（配合 Python 2）或 $\geq$ 3.0.3（配合 Python 3），生成 DOLFIN 和 mshr 的 Python 接口所需工具；flufl.lock，在 NFS 文件系统上实现文件锁定（由 Instant 使用）；HDF5，提供并行、可扩展 IO 后端，需要以并行支持构建 [The HDF Group, 2015]；zlib，读取压缩 XML 文件和压缩 VTK 输出；VTK $\geq$ 5.2，在 DOLFIN 中提供交互式绘图；CGAL 4.5.1、TetGen 1.5.0，mshr 后端，由 mshr 构建系统自动构建 [The CGAL Project, 2015, Si, 2015]；GMP、MPFR，任意精度和多精度算术库，mshr 需要 [Granlund and the GMP development team, 2014, Fousse et al., 2007]；Scipy，UFL 评估误差和 Bessel 函数需要；pytest，Python 测试工具，运行单元测试需要；Sphinx $\geq 1.1.0$，支持构建文档；Qt4，提供编写图形应用的 API；Soya，Python 3D 引擎，用于绘制有限元。
