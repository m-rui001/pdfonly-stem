# 基于区块链的异构智能交通系统动态密钥管理

**原文标题**: Blockchain-Based Dynamic Key Management for Heterogeneous Intelligent Transportation Systems (2017, IEEE Internet of Things Journal) · DOI: https://doi.org/10.1109/jiot.2017.2740569

本文提出一种面向异构车联网（VCS）的密钥管理框架，用区块链结构替代传统分层网络中的中央管理器（CA），将密钥传输握手从经CA的多跳转发简化为SM网络内部挖矿验证，并引入动态交易收集周期以降低车辆跨域切换时的密钥交付时延。作者通过仿真证明：在交易数少于约1500时，区块链结构的密钥传输时间明显低于传统结构；动态收集周期则能在不同交通强度下持续占据最小时间成本。

## 一、背景与相关工作

VCS安全依赖安全信标消息（欧洲称CAM，美国称BSM）的加密，其可信性由预共享的组密钥（GK）保证，因此ITS安全问题可归结为组密钥的可靠分发与更新。传统密钥树和批重密钥方法不适用于节点规模巨大的VCS。异构性既体现在交通量差异，也体现在不同网络结构或不同中央管理者；当车辆跨域时，前一个安全域的管理者（SM）必须及时将车辆密码材料转交给邻居SM。区块链作为同步的分布式账本，可移除中央管理者，由所有SM共同维护账本并验证交易，从而加速跨域信息传播，且对单点故障更鲁棒。相关工作回顾了CPS安全与效率挑战、区块链在加密货币、个人数据管理和智能电网能源交易中的应用；指出此前没有将区块链用于VCS的工作，作者的前期工作[34]首次将SM网络用于跨域车辆密钥的传输与验证，但未考虑信息校验时间和动态交通因素。

## 二、所提框架

**系统模型与网络结构**
系统假设基础设施配备IEEE 802.11p无线模块，车辆装有OBU，周期性发送包含速度、方向、位置、尺寸的安全消息；基础设施将消息转发给上层的SM，每个SM管理一个安全域。传统VCS网络分四层：RSU、SM、CA（中央管理器）和用户层。车辆从域A到域B跨域时，Previous SM（SM-A）检测到跨界行为，生成跨界请求，经CA-A验证后转发给CA-B，CA-B再转发给SM-B，触发重密钥。该过程需要多次握手，时延高。区块链结构将中央管理器功能合并到SM中，CA只作为隔离设施存储和生成车辆密码材料（初始注册、周期性更换假名、对抗撤销三种情形下访问）。SM作为矿工，把跨界活动的安全消息封装成交易，收集成块并广播；新加入成员的密钥通过检索区块获得。

**跨域密钥传输握手**
传统跨域握手过程（图3）中，SM-A将交易逐个发送给CA-A验证（解密后用CA-B公钥重加密），CA-B重复验证后转给SM-B。同域内（图4）则只需一个CA转发。区块链结构（图5）中，SM-A直接将交易发送到SM网络（SM-Cloud），网络矿工验证签名、保留密文（用目的SM公钥加密），将交易随机排序装入区块并挖矿，再把挖好的区块广播回网络。交易格式（表I）包含交易号、当前SM号、目的SM号、加密的车辆身份材料（假名和证书）以及签名；密文用目的SM公钥加密，因此SM网络无法读取，签名保证认证、完整性和不可否认性。区块头（表II）含版本、前一区块哈希、Merkle根、时间戳、目标难度、nonce；区块负载由收集期tCP内收集的交易组成。交易数nT = (nH × tCP)/3600，其中nH为每小时车辆数。挖矿使用双重SHA256（dhash），随机交易顺序使不同SM的挖矿时间不同，避免区块冲突；算法1和算法2分别给出计算nonce和验证区块的伪代码。

**时间组成与动态收集周期**
密钥传输时间由准备时间tprep、传输时间ttransfer（含CSMA退避tBO和线路传播tP）和处理时间tprocessing（含加密tE、解密tD、签名tS、验证tV）组成。传统跨域处理时间tTC = nT×(tV+tD+tE+tS)×2 + (tBO+tP)×3；同域tTS = nT×(tV+tD+tE+tS) + (tBO+tP)×2；区块链tB = nT×tV + (tBO+tP)×2 + tprep + tM，其中tM为挖矿时间，tprep包括随机排序trand、填充tfill、Merkle根tmerkle和头处理theader。动态密钥管理通过改变交易收集期实现：设nR条道路，tCP可变，则在1秒内的平均时间tB-1 = [nT-All×tV + (tBO+tP)×2 + tprep + tM] ÷ tCP，其中nT-All = (traffic amount × tCP × nR)/3600。通过优化算法（算法3）在可选tCP集合中选取使tB-1最小的值。

## 三、性能评估

**仿真设置与密码学处理时间**
使用OMNeT++ 4.5与Veins仿真，ECIES和ECDSA均基于secp160r1曲线（Crypto++库）。密码块长75字节，跨界信息20字节，区块难度设为3。用Intel Core i5、8GB RAM、GeForce 920M的笔记本模拟挖矿，每秒可完成25万次哈希。前两部分仿真不考虑车辆移动，只看交易总数（0到2000）。第三部分假设车辆跨界事件服从指数分布，事件发生率λ = 1/μ，生成时间ti = -ln(1-Pi)/λ；低峰交通为3000辆/小时/路，饱和交通为15000辆/小时/路。北京8个城区组成3×3拓扑（图6），每边有5条双向高速，共120条公路。每个SM的tCP在0.5到1秒间变化。

**密码学处理时间与区块准备**
各密码方案的平均处理时间（表IV）：ECIES加密0.51027 ms、解密0.73996 ms、ECDSA签名0.51011 ms、验证1.10171 ms、区块挖矿4.11046 ms。除挖矿外，处理时间随交易数线性增长；挖矿时间恒定（只挖一个头）。区块准备时间（图8）随交易数指数增长：在300交易前缓慢增加，400交易时超过0.1秒，1000交易时达0.95秒；非线性增长主要来自随机排列trand。

**区块链与传统结构对比**
对比两种情境：同安全区内的域间切换（图9a）和跨安全区（图9b）。区块链结构在500交易时约0.8秒，传统结构约为两倍，传统握手法（[37][38]）则超过三倍。两条曲线在约1500交易处相交，之后区块链因指数增长而耗时超过传统，但区块链在少于1500交易时具有更好的可扩展性，且1500交易处节省近一半处理时间，2000交易时仍低于基准。跨安全区情境中，传统结构需要两个CA通信，额外握手导致时延剧增：传统结构和传统握手法在交易数分别超过1750和800时耗时超过10秒，区块链结构始终显著更低。

**动态交易收集周期的效果**
图10显示平均交易数与交通量和收集期成正比；每tCP每流量平均交易数 = nH×tCP/3600，再乘道路数nR得总交易数。图11显示各tCP下，收集期超过0.8秒后处理时间急剧上升；例如1秒收集期在15000辆/小时/路时捕获4.2交易，12000时捕获3.3，差108笔交易导致巨大时延差异。以1秒为标准度量，图12(a)显示不同交通强度下最小处理时间对应的tCP不同：轻交通下较长收集期更优，重交通下短收集期更好；图12(b)显示动态选择方案始终处于最小时间曲线。图13显示节省时间比例：重交通下高频收集（短tCP）节省比例较低，而长收集期在高峰交通下额外耗时超过10%，因此高交通下短tCP更经济，低交通下短tCP反而耗时更长。

## 四、结论

本文提出基于区块链的VCS异构密钥管理方案，用去中心化SM网络替代中央CA，简化密钥传输，并通过动态交易收集期优化时延。仿真表明，区块链结构在交易数较少时比传统结构更高效，动态方案能灵活适应不同交通水平。未来工作将把区块链用于假名管理，并让用户在安全与隐私间进行权衡。
