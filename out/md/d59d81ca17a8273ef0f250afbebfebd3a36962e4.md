# Uppaal SMC 教程：随机混成系统的统计模型检验

*Uppaal SMC tutorial · 2015 · https://doi.org/10.1007/s10009-014-0361-y*

本文介绍 Uppaal 家族中用于带随机语义的实时系统网络的统计模型检验工具 Uppaal SMC。它的核心主张是：通过随机解释定时自动机（STA）并用统计模型检验（SMC）替代穷尽状态空间探索，可以在不可判定的一般混成随机模型上高效评估性能属性（如概率、假设检验、概率比较），同时保持与传统 Uppaal 建模语言的兼容，并支持动态进程创建、ODE 和自定义分布等扩展。

## 1 背景与建模形式

计算机系统错误可能造成严重后果，形式化方法中的模型检验能保证设计无 bug，但经典定时自动机（TA）模型无法刻画复杂信息物理系统中丰富的连续动力学和随机行为，其模型检验问题一般不可判定。Uppaal SMC 为此提出替代方案：系统由网络化的自动机组成，时钟可带不同速率甚至由常微分方程（ODE）指定，延迟由概率分布决定，并用统计模型检验来监控仿真结果，借助序贯假设检验或蒙特卡洛方法以一定置信度判定属性。SMC 比穷尽方法更省内存和时间，且更适合工业应用，已在系统生物学、能源、航空电子等领域流行。

Uppaal SMC 的建模形式是对经典 TA 的随机解释：原有多个使能变迁之间的非确定性选择被概率选择（可带权重）取代；延迟的非确定性选择被分布取代——有界延迟用均匀分布，无界延迟用指数分布（速率由用户指定）。例如三个自动机 A1、A2、A3（原文 Fig.1）：A1 的三条边延迟均自动取 [2,4] 上的均匀分布，总到达时间是三者的和（Fig.2a）；A2 上下路径分别由均匀分布之和给出，总延迟是两条路径的组合（Fig.2b）；A3 无不变式，延迟服从指数分布（速率各为 1/2、1/2、4），且初始有离散概率选择（1/4 对 3/4），得到 Fig.2c 的分布。这些分布与经典语义下时间区间一致：A1 支持区间 [6,12]，A2 为 [4,12]。这类随机定时自动机包含离散和连续时间马尔可夫链，其到达时间分布涵盖相位型分布。

多个 STA 通过广播同步和共享变量组成网络，要求各组件输入使能、确定（后继集上有概率测度）且非 Zeno。组件间反复“竞赛”：每个组件独立随机决定输出前延迟多久，最小延迟者获胜。例如 Fig.3 中 (A|B|T) 从 (A0,B0,T0) 到 T3 的转移序列中，A 初始以 0.75 概率赢得竞赛。虽然单个 STA 语义简单，但通过消息传递混合各分布的组合可产生任意复杂随机行为。

建模语言还支持整数变量、数据结构、自定义函数，以及任意（整数）速率的时钟和带权重的分支边。为说明扩展，原文给出列车-门禁例子（改编自[41]）：多列火车接近单轨桥梁，控制器停车保证安全。火车模板中 Safe 位置无不变式，延迟服从指数分布，速率表达式为 (1+id)/N^2（id 为火车标识，N 为数量），故 id 越大到达越快；Appr、Cross、Start 等位置有不变式，延迟取均匀分布，如过桥时间为 [3,5] 均匀。门控制器用队列数据结构管理列车。

## 2 查询语言与统计算法

Uppaal SMC 保留经典可达性、不变性等查询，并新增随机解释相关查询。模拟查询语法为 `simulate N [<=bound] { E1,..,Ek }`，可监控表达式的值，如对列车门模型 `simulate 1 [<=300] { Train(0).Cross, Train(5).Cross, Gate.len}` 可观察两列火车过桥和队列长度（Fig.6）。属性语法基于加权 MITL：`ϕ ::= ap | ¬ϕ | ϕ1 ∧ ϕ2 | Oϕ | ϕ1 Ux≤d ϕ2`，其中 ap 是状态谓词合取，d 为自然数，x 是时钟。对一般加权 MITL 公式，PM(ϕ)≥p 不可判定；但对有界可达类 `PM(3x≤C ap)≥p` 可用 SMC 近似。三种基本问题：概率估计、假设检验、概率比较。

**概率估计**：将每次运行编码为伯努利变量，用 Clopper-Pearson“精确”法基于二项分布给出置信区间，并采用序贯方法——每新增一次仿真就更新区间，当宽度小于 2ε 时停止。相比 Chernoff-Hoeffding 不等式，序贯法更高效，尤其当概率接近 1/2 时更好。查询 `Pr[<=100](<> Train(0).Cross)` 和 `Pr[<=100](<> Train(5).Cross)` 分别返回 95% 置信区间 [0.502421,0.602316]（383 次运行）和 [0.902606,1]（36 次运行），证实 Train(5) 到达概率更高。

**假设检验**：检验 H0: p≥θ 与 H1: p<θ，用强度参数 α（假阳性）和 β（假阴性），测试 H0: p≥θ+δ+ 与 H1: p≤θ−δ−，采用 Wald 序贯检验。查询 `Pr[<=100] (<> Train(0).Cross) >= 0.2` 仅需远少于 383 次的运行即可确认；重复 5 次分别用了 66、62、65、67、49 次运行（5% 显著性）。

**概率比较**：检验 `Pr[<=100](<>Train(5).Cross) >= Pr[<=100](<>Train(0).Cross)`，在 120（132、144、108、174）次运行内确认（5% 显著性）。

此外支持期望值查询 `E[bound;N](min:expr)` 或 `E[bound;N](max:expr)`，用 Student t 分布给出置信区间。例：`E[<=20; 20000](max: sum(i:id_t) Train(i).Stop)` 估计前 20 时间单位内最大停车列车数的平均值，置信区间 3.64775 ±0.0126354（20000 次运行）。

对于完整加权 MITL，实现通过构造确定性的下/上近似监控 PTA，与模型并行并在线重写公式。查询语法含 `(ψ U[a,b] ψ)`、`(ψ R[a,b] ψ)`、`<>[a,b] ψ`、`[][a,b] ψ` 等。例如 `Pr( <>[10,100] ([][0,5] Train(0).Stop) )` 表明 Train(0) 在 [10,100] 内停车至少连续 5 时间单位的概率高，738 次运行给出 95% 置信区间 [0.880894,0.980894]。

## 3 扩展到混成系统与动态进程

Uppaal SMC 支持随机混成系统：时钟速率可由含时钟的一般表达式给出，即 ODE。示例为两个房间共享一个加热器。加热器开启时间在 [0,4] 均匀，以 1/4 概率选房间 0、3/4 选房间 1，保持时间服从指数分布（房间 0 速率 2、房间 1 速率 1）。房间温度由 ODE 决定：未加热时 Ti' = -Ti/10 + sum_j A[i][j]*(Tj-Ti)/s，加热时 Ti' = K - Ti/10 + sum_j A[i][j]*(Tj-Ti)/s，K 在 [9,12] 均匀（K=9+random(3))。用查询 `simulate 1 [<=600] { T[0], T[1] }` 可绘图（Fig.12）。查询 `Pr[<=100]([] Room(0).Init || T[0] <= 20)` 和 `Pr[<=100]([] Room(1).Init || T[1] >= 7 )` 分别返回 [0.45,0.55] 和 [0.65,0.75]，前者需 738 次运行（精度 ±0.05，置信 95%）。而假设检验 `Pr[<=100]([] Room(1).Init || T[1] >= 7) >= 0.69` 仅需 902 次运行（95% 显著性）；若用概率检验同精度需 ±0.005 则需 73778 次运行。比较查询 `Pr[<=100]([] Room(1).Init || T[1] >= 7 ) >= Pr[<=100]([] Room(0).Init || T[0] <= 20)` 仅需 258 次运行。注意 ODE 解算器为固定步长欧拉法，可能对刚性系统不稳定。

支持 double 浮点类型，但若在模型中使用浮点运算或混合时钟，模型记为 hybrid，此时除非时钟为 hybrid 时钟且不影响控制（仅作成本），否则禁用模型检验。

动态进程创建：标准 Uppaal 需预知最大线程数并建模资源管理器，Uppaal SMC 原生支持动态 spawn。任何自动机可 spawn 声明为动态的模板，动态实例可随时 exit() 终止。示例为客户端-服务器模型：10 个服务器监听 req 通道，客户端有 id，spawn 时传入参数。动态模板用 `dynamic Client(int id)` 声明，参数限制为传值或广播通道引用。查询语言增加 `forall(i:T)(q)`、`exists(i:T)(q)` 和 `sum(i:T)(a)`，还可用 `numOf(Client)` 计数。例如 `Pr(<>[0,20] (exists(c:Client) ([][0,5]c.Wait)))` 检查客户端等待 5 时间单位的概率；`sum(c:Client)(c.Wait)` 统计等待客户端数。`simulate 1 [<=100] { foreach(c:Client) (3*c.id+c.Wait+2*c.Work) }` 可得到每个客户端生命周期的甘特图（Fig.15）。

## 4 图形界面与建模技巧

图形界面分为编辑器、两个模拟器（符号模拟器和具体模拟器）和验证器。具体模拟器支持具体时钟值、消息序列图、变量查看和甘特图。甘特图可在系统声明中定义，如 `gantt { gate: Gate.Occ -> 0, Gate.Free -> 1; train(i:id_t): Train(i).Appr -> 2, ... }`。统计参数选项包括 δ+/δ− 定义无差异区、α/β 控制错误概率、ε 为概率评估的不确定性、u0/u1 为概率比较的上下界，还有直方图参数和 ODE 离散步长。

建模技巧：
1. **转换握手同步为广播同步**：一对一同步可直接重声明通道为 broadcast，把接收者守卫移到发送者并用整数记录接收者位置；一对多同步需复制发送边并重命名通道，可用数组和 select 构造；若接收者有不变式则无法转换，因为会违反独立进展条件。无不变式且带输出同步的位置需添加指数速率。
2. **编码自定义分布**：模式是进入 Wait 位置时计算延迟存到时钟 delay，用 `delay'==0` 保持，然后延迟该量后转换。函数 f() 可用 `random(n)` 生成均匀数再变换，如 Box-Müller 法生成正态分布（Listing 1），返回 double。推荐用时钟而非 double 变量存延迟，因为浮点表达式会触发过细离散化降低性能。
3. **建模物理**：仅支持一阶导数，n 阶导数需引入中间时钟变量，如 y'' 拆成 y'==v 和 v'==-9.81。
4. **建模生物化学**：化学反应 γ A + 2B → C + 3D 可建模为随机模型（整数分子数 A=100,B=200，速率 gamma*A*B*B 的指数分布）或动力学模型（用 ODE 表达 d[A]/dt = -γ·[A]·[B]^2 等）。随机模型轨迹抖动，动力学模型平滑且确定。缩放量时需注意溢出：默认 int 范围 ±2^16，可自定义 int32_t 范围，或扩大到 double 但精度仅 52 位比特（约 4.5e12）。
5. **获取成本分布**：用 `Pr[E<=10](<> t==2)` 这类技巧，把 E 作为时钟积分能量，t 作为时间边界，得到能耗分布直方图。默认设置精度差，需调 α=0.001、ε=0.0005，7598 次运行得到 Fig.28c。也可用时钟手动维护离散计数器。
6. **自定义离散化**：在需要细步长的位置使用“高”指数速率，使工具以小而随机的步长推进，如用 `T = T - (T*dt)/KCOOL` 等手动积分函数，替换 T'==-T/KCOOL。注意常数速率不构成 ODE，只有 x'==y 才触发积分。

结论：Uppaal SMC 可高效评估随机混成系统的性能属性，建模语言支持动态行为、离散概率、随机延迟和进程创建，远超出解析工具的范围。旧 Uppaal 模型只需小改动即可获得性能度量；未来计划改进 ODE 解算器和仿真器可视化。
