# Phenix——面向大分子结构解析的综合 Python 系统

*Phenix - A Comprehensive Python-based System for Macromolecular Structure Solution*（LA-UR-09-06138；拟发表于 Acta Crystallographica D / International Tables of Crystallography）

本文介绍 Phenix：一个面向大分子晶体学结构解析的综合软件系统，其核心主张是把结构解析各环节建立在以 Python 脚本层为中枢、C/C++ 编译模块承担数值密集计算的混合架构之上，从而以自动化减少主观输入与手工操作，并把原本分散的工具紧密集成。摘要指出，大分子 X 射线晶体学虽已常规用于在分子层面理解生物过程，但由于需要借助众多软件包人工解读复杂数值数据、反复使用交互式三维图形，解析并完成许多结构仍耗时费力；Phenix 因此强调对所有流程的自动化，其依托是三类算法工作：最小化或消除主观输入的算法、将传统手工流程自动化的算法，以及使各算法紧密集成的框架。

## 架构与图形界面

Phenix 的架构从底层起就被设计为解释型（“脚本化”）模块与编译模块紧密集成的混合系统。作者指出，脚本与编译组件混用在所有主流成功的晶体学软件包中都存在，但脚本往往是以临时方式事后添加、所用工具早于面向对象时代；这类临时系统虽建立迅速，却随规模增长成为沉重维护负担，用户也常被迫承担手工转换文件格式等耗时例行任务。与之相对，Phenix 把脚本层置于系统核心：除少数例外，所有主要功能都实现为仅通过脚本接口访问的模块，所用语言为面向对象的 Python。作者强调，约二十年间庞大的开发者/用户社区已产出数百万行高度统一、可互操作、成熟且公开可用的源码，覆盖从简单文件处理到复杂网络通信与完整跨平台图形界面的各方面；把晶体学方法嵌入这一环境可带来空前的自动化程度、稳定性与可移植性，而面向对象编程模型也促进多组共享协作开发，把不同小组编写的模块按层次重组为对外观感一致的更复杂流程。脚本语言通常最适合快速开发新算法，但运行时性能考虑常要求数值密集计算最终以编译语言实现，首选即与脚本语言同一语言环境——C/C++ 环境；这一 Python 与 C++ 结合的模式贯穿整个 Phenix 系统。

Phenix 在 1.4 版引入新的图形用户界面（GUI），使用开源 wxPython 工具包，在各操作系统上提供“原生”外观。开发重点是在尽量少改动的前提下为既有命令行程序提供界面，并以多数 Phenix 程序所用的同一底层配置系统 libtbx.phil 为模板自动生成控件。由于这些程序主要以 Python 模块实现，模型、反射数据及其他可查看数据可与 GUI 交换而无需解析日志文件。当前 1.5 版包含 phenix.refine、phenix.xtriage、AutoSol、AutoBuild 与 LigandFit 向导、 restraints 编辑器 REEL、所有验证工具，以及若干创建和操作 map 与反射文件的实用程序；较新的 nightly build 含 AutoMR 向导的新 GUI，未来版本将包含 Phaser 的新界面。本质上是图形的数据用嵌入式图表（免费的 matplotlib Python 库）或简单 OpenGL 查看器可视化，这简化了 phenix.refine 中原子选择等最复杂参数——可交互可视化或拾取。GUI 也是进一步自动化与用户定制的平台：类似 CCP4 界面 ccp4i，Phenix 为各用户自定义项目管理数据与任务历史，可为每个项目指定默认参数与输入文件，例如从 phenix.refine GUI 生成配体 restraints 时可选择在后续运行中自动加载。Python 作为科学编程语言的流行使其被用于许多其他结构生物学应用，尤其是分子图形软件；Phenix GUI 包含建模程序 Coot 与 PyMOL 的扩展模块，二者均通过 XML-RPC 协议由 Phenix 远程控制，使界面无缝集成——Phenix 中任何模型或 map 可一键在 Coot 中打开；在 AutoBuild、phenix.refine 等迭代重建或精修的程序中，当前模型与 map 一旦可用便会在 Coot 和/或 PyMOL 中持续更新；对验证工具，点击任何被标记统计不佳的原子或残基会使图形窗口重新居中到该原子。用同一协议远程控制 Phenix GUI 也很简单，对 Coot 界面的简单扩展可直接以预载模型启动 phenix.refine。

## 实验数据分析、定相与模型构建

Phenix 提供一系列分析、验证和操作 X 射线衍射数据的工具。综合分析工具 Xtriage 执行从空间群、孪晶到异常信号检测的检验，为使用者和 Wizards 提供刻画数据集的统计量；对孪晶分析，phenix.xtriage 汇总多项统计以对可能的对称性与孪晶相关问题给出平衡判断，并向用户反馈数据总体特征。在数据收集期间或之后常规使用 phenix.xtriage 已促成及时发现孪晶或其他问题，这类数据特异性的检测通常减少成功解析结构的总体工作量。其中，整体各向异性比例因子用 Bourenkov & Popov (2003) 的似然形式做基于似然的估计；用数据库导出的蛋白质与核酸标准 Wilson 图检测平均强度异常，异常可能源于冰环或其他问题；还分析数据强度与低分辨率完整性。异常信号的存在通过分析 measurability 检测，该量表示数据集中统计显著的 Bijvoet 差异所占比例。天然 Patterson 函数用于检测赝平移对称性，并用数据库导出的最大峰高经验分布为 Patterson 函数中检测到的峰赋予显著性。系统还执行全面的自动孪晶分析：从第一性原理导出孪晶律以识别赝孪晶（pseudo-merohedral）情形；在按数据强度分析建议的分辨率截断后的数据上导出振幅与强度比、$< |E^{2}-1|>$ 值、L 统计量以及 NZ 图；去除噪声相对较高的数据壳层可显著改善这些统计量的自动解读；当存在孪晶律时，用 Britton 图、H 检验和似然导出方法估计孪晶分数；若已提供模型，则进行 R vs R 分析，此类分析在处理赝对称、空间群问题和孪晶时特别有用。为检验不同数据集间索引不一致，依据样品与参考数据集的晶胞和空间群从第一性原理导出一组重索引律，相关分析给出最可能的重索引选择；对晶胞度规对称性的分析给出若干可能点群，用受似然启发的方法建议最可能的点群，随后在似然框架下分析系统消光以对后续空间群可能性排序（细节待发表）。

在确认衍射数据可靠且被理解之后，解析结构的下一个关键需求是通过若干策略之一确定相位。亚结构测定程序 phenix.hyss（Hybrid Substructure Search）把 Shake-and-Bake 与后来 SHELXD 开创的多轮双空间循环方法与快速平移函数结合；快速平移函数是在倒空间进行的 Patterson 函数系统搜索的基础，与 SHELXD 在直接空间进行的随机替代方案相对。作者称 phenix.hyss 是唯一通过 Euclidean Model Matching 程序（cctbx 开源库的一部分）完全集成多轮试验中亚结构自动比较的亚结构测定程序，这使其能检测同一解是否被多次找到并在这种情况下自动终止；对多种 SAD 数据集的广泛测试导出了一套参数化方案，平衡运行时间与重复解代表正确亚结构的可能性，在许多情况下若亚结构可从输入数据中检测到，该过程可在数秒内完成。Phaser 在 Phenix 中以 phenix.phaser 提供，把最大似然原理应用于分子置换、单波长异常衍射（SAD）或二者结合来解析晶体结构；似然目标函数恰当考虑不同误差来源的影响（在 SAD 定相中还包括其相关性），并允许组合不同来源的信息；在含多个组分的分子置换问题中，部分解获得的信息可增强搜索后续组分的信号；由于不同模型的似然分数可直接比较，模型间决策可方便地作为自动化策略的一部分。

非晶体学对称性（NCS）是许多大分子晶体的重要特征，可用于大幅改善电子密度图。Phenix 有识别 NCS 以及利用 NCS 和大分子多晶型进行相位改进的工具：phenix.find_ncs 与 phenix.simple_ncs_from_pdb 利用重原子亚结构或原子模型信息识别结构中的 NCS，前者可从重原子亚结构或 PDB 文件中的链识别 NCS，再与 map 中的密度比较以验证 NCS 确实存在；phenix.multi_crystal_average 是组合结构多个晶型信息的方法，特别适合每个晶型有自身 NCS 的情形，它调整各晶型的相位使所有晶体中所有 NCS 拷贝尽可能相似。作者建议，除有明确证据表明不存在 NCS 外，密度修饰和模型构建中通常都应施加 NCS restraints：在 Phenix 的密度修饰中，NCS 的存在由重原子位点或可用的原子模型识别，随后用 NCS 相关位置密度的局部相关性自动设置 map 中 NCS 对称性的可变 restraints；在精修中，NCS 对称性通过坐标 restraints 施加，目标是各 NCS 拷贝相对于其他 NCS 相关链的位置。Phenix 默认 NCS restraints 很紧，目标为 0.05 Å rms；在低于约 2.5 Å 的分辨率下通常应施加这些紧 restraints，更高分辨率时可能适合使用更松的 restraints 或完全去除；此外，若链中某些片段明显不遵守 NCS 关系，应将其排除在 NCS restraints 之外，通常自动完成，也可显式指定。

## 模型构建、配体拟合与核酸

分析大分子晶体结构的关键步骤包括构建初始核心模型、识别并将配体拟合进电子密度图，以及为比结构大部分定义更差的环区构建原子模型。Phenix 有快速构建二级结构与主链追踪的工具 phenix.find_helices_strands、拟合柔性配体的 phenix.ligandfit、把一组配体拟合到 map 的 phenix.find_all_ligands、在 map 中识别配体的 phenix.ligand_identification，以及拟合缺失环的 phenix.fit_loops；并提供验证工具，使产生的模型可在每一步得到验证。phenix.find_helices_strands 可快速把仅含二级结构的模型构建进 map，或极快地追踪多肽主链：构建二级结构时，它识别 $\alpha$ 螺旋区域与 $\beta$ 链段，将理想化螺旋与链建模进相应密度（允许螺旋与链弯曲），并组装成复合模型；极快追踪主链时，它沿高密度脊线寻找可能为 $C_{\alpha}$ 原子的点，识别其间有密度且几何合理的 $C_{\alpha}$ 原子对与三元组，把这些 $C_{\alpha}$ 原子所有可能连接构造成 9-mers，再识别通过连接 9-mers 能得到的所有最长可能链。该过程可以约 20 残基/秒的速度构建 $C_{\alpha}$ 模型，产生可直观或自动解读以评估其所依据 map 质量的主链模型。phenix.fit_loops 拟合原子模型中缺失的环，使用 RESOLVE 模型构建从缺失环的任一端延伸链，并以预期残基数把链连接成环。

配体拟合方面，phenix.ligandfit 把柔性配体拟合进电子密度图，关键做法是把配体拆成刚性体部件，寻找每个部件可放置到密度中的位置，基于这些核心刚性体部件的位置追踪配体其余部分，并基于对密度的拟合打分重新组合多次拟合中最好的部分。phenix.find_all_ligands 在电子密度图中寻找若干配体各自的全部实例：它找到 map 中未使用密度的最大连续区域，用 phenix.ligandfit 把每个给定配体拟合进该密度，然后选择与密度实空间相关性最高的配体，重复此过程直到无法再把任何配体满意地拟合进 map 中剩余密度。phenix.ligand_identification 识别哪些配体与 map 中未知电子密度相容，可用 PDB 中最常见的 200 个配体或用户提供的配体列表搜索；它用 phenix.ligandfit 把每个配体拟合到 map，并用实空间相关性以及配体与配体结合位点周围原子之间的表面互补性识别最佳拟合配体。

与多数晶体学工具一样，Phenix 最初主要面向蛋白质结构开发；随着核酸尤其是 RNA 在大型生物结构中日益重要，系统正在需要细微流程差异之处（而不仅是相关库）进行修改。phenix.autobuild 的模型构建现在有初步的核酸流程，利用相对确定得较好的磷酸与碱基位置以及双螺旋的普遍性，并使用 RNA Ontology Consortium 最近定义的 RNA 主链构象。核酸结构显著受益于最近加入 phenix.refine 选项的扭转角精修。RNA 模型的一个主要问题是正确获得核糖 pucker，尽管已知其几乎完全由 C3'-endo（更常见，A 型螺旋中的那种）或 C2'-endo 组成；MolProbity 使用从 3' 磷酸到 C1'-N1/9 糖苷键连线的垂直距离作为核糖 pucker 的可靠诊断，该检验现已被内置到 phenix.refine 中，以便使用 pucker 特异的键长、键角和扭转角目标参数，而非多数不区分 pucker 的精修中使用的勉强折中值。目前若诊断出错误 pucker，通常必须由用户重建修复，例如在 Coot 或 RNABC 中；重建功能可能很快被纳入 Phenix，但与此同时，一旦用构象特异残基名构建并识别出 C2'-endo pucker，精修将正确维持其几何。

关于 map、模型与避免偏倚，phenix.refine（以及图形工具 phenix.create_maps）可产生多种 map，包括异常差异图、最大似然加权的 $( p^{} \mathrm{m F_{o b s}}-q^{} \mathrm{D F_{m o d e l}}) \exp(\mathrm{i} \alpha_{\mathrm{m o d e l}})$ 与常规的 $( p^{} \mathrm{F_{o b s}}- q^{} \mathrm{F_{m o d e l}}) \exp(\mathrm{i} \alpha_{\mathrm{m o d e l}})$（其中 p 和 q 是任意用户定义数）、filled 与 kick map；似然加权 map 的系数 m 和 D 使用 test set 反射按 Lunin & Skovoroda (1995) 与 Urzhumtsev 等 (1996) 所述计算。数据不完整，尤其是系统性不完整，会造成 map 畸变；一种补救方法是用非零值替换（“填充”）缺失观测：可用 $\mathrm{DF_{model}}$（类似 REFMAC）替换缺失的 $F_{\mathrm{obs}}$，或在缺失 $F_{\mathrm{obs}}$ 值周围的分辨率 bin 中对 Fobs 取平均后替换 $< F_{\mathrm{obs}} >$。基于有限测试，两种“填充”方案产生相似结果，重申了相位的重要性；但必须记住，替换缺失 Fobs 有引入偏倚的风险，数据越不完整风险越大，目前建议同时使用填充与未填充两种 map。平均 kick map（AK map）由以下过程产生：创建大量结构集合，其中每个结构的坐标都被随机抖动，然后为每个结构计算 map，最后平均所有 map 生成一张平均 kick map；AK map 预期偏倚更少、噪声更少、增强已有信号，并可能澄清一些初始较差的密度。一种计算密集但强大的极低偏倚 map 创建方法，是在所有结构因子计算中省略 map 的一个区域，同时进行迭代模型构建与精修；phenix.autobuild 的 iterative-build OMIT map 流程可对单个 OMIT 区域或重叠 OMIT 区域自动执行此操作，生成复合 iterative-build OMIT map。

## 验证、精修与集成式结构解析

晶体学结构解析的结果是原子模型，评估模型质量有三个主要方面：模型几何与立体化学质量，以及模型与数据在实空间和倒空间中的拟合质量；三者都提供整体度量，前两方面还提供局部离群检查（实验数据验证见上文第 2 节）。Phenix 包含许多针对特定验证方面的单独工具，以及若干把结果组合成总体摘要的系统；验证既用于用户评估结构解析的进展与结果，也用于帮助其他部分的自动化选择。MolProbity 模型验证工具的大部分方面已被改编或重写以在 Phenix 中集成使用，并通过新 GUI 呈现给用户。氢原子由 phenix.reduce 添加，优化整个局部氢键网络，考虑第一层晶体学水，并可选择修正侧链酰胺或组氨酸 $180^{\circ}$ “flips”。全原子接触由 phenix.probe 计算，提供验证严重全原子立体冲突所需的原子重叠信息，也可在 Coot 中可视化。对 Phenix GUI，基于 MolProbity 的工具集既提供整体模型统计（如 clashscore 和百分位离群值），也提供 Ramachandran、rotamer、C$\beta$ 偏差和冲突离群值的详细列表；这些验证方法有命令行工具 phenix.rotalyze、phenix.ramalyze、phenix.cbetadev、phenix.clashscore、phenix.reduce 和 phenix.probe。此外，phenix.validate_model 分析键长、键角、平面性等相对理想库值的偏差，补充 MolProbity 的扭转与立体工具。phenix.real_space_correlation 通过在残基或原子水平（取决于分辨率）定量衡量原子模型对电子密度图的拟合，断言局部模型与数据的对应关系。快速获得晶体学模型及相关实验数据的全局品质因子快照，是结构解析各阶段常做的任务；该任务可能因 PDB 格式坐标文件中存在新配体或非标准残基、孪晶晶体收集的数据、各种反射数据文件格式、存在 TLS 时原子位移参数的不同表示、实验数据类型（X 射线、中子或联合）、含多个模型的文件以及各种格式问题而复杂化。phenix.model_vs_data 设计为以最少用户输入（一个 PDB 文件和一个反射数据文件）自动处理所有这些复杂情况，并提供简明摘要输出。phenix.polygon 是图形工具，用于指示某结构相对于 PDB 中已沉积结构的验证参数（如 free-R 值）的相似性，比较针对所有在相似分辨率极限下解析的其他结构，结果以图形呈现。phenix.validation 把上述所有工具组合在一个 GUI 中，为评估结构解析结果提供单一场所。

在模型与结构因子操作和分析方面，Phenix 有一系列显示、分析和操作结构因子与模型信息的工具：phenix.mtz.dump 和 phenix.cif_as_mtz 显示并转换结构因子数据；phenix.print_sequence、phenix.pdb_atom_selection 和 phenix.pdbtools 显示并操作坐标文件。phenix.tls 是提取和操作 TLS 信息的工具，可从 REFMAC 或 Phenix 格式的 PDB 文件头提取 TLS 矩阵与选择，并计算输出总或残余原子 B 因子；未来功能将包括 TLS 矩阵的完整分析及其图形可视化。phenix.get_cc_mtz_mtz 和 phenix.get_cc_mtz_pdb 用于分析一对 MTZ 文件所基于的 map 之间、或由 MTZ 文件与 PDB 文件计算的 map 之间的一致性；这些工具的关键属性是自动搜索可能关联两张 map 的所有允许原点位移，并写出其中一个 MTZ 文件或 PDB 文件的修改版本，位移以匹配另一个。

结构精修方面，phenix.refine 是 Phenix 中最先进的晶体学结构精修引擎，其基础精修机制是高效编程工具与新提出或重新思考的晶体学算法的结合。它拥有覆盖大多数精修场景的广泛工具集，适用于从低到超高分辨率的任何数据分辨率；可自动识别各种反射数据格式（例如 CNS、MTZ 和 SHELX）；输入实验数据被检查离群值，识别出的反射被排除在精修计算之外；可通过提供孪晶律算符考虑孪晶，该算符可用 phenix.xtriage 获得。X 射线和/或中子衍射数据均可使用，并有联合 XN 精修选项（同时针对 X 射线和中子数据精修）。每次精修运行以稳健的基于 mask 的体相溶剂校正和各向异性缩放开始。高效刚体精修（多区算法）、在笛卡尔或扭转角空间的模拟退火精修、自动 NCS 检测及其作为 restraints 在精修中的使用等工具，在低分辨率和精修初始阶段很重要。可用的原子位移参数化范围广泛，包括分组各向同性、约束各向异性（TLS）、单原子各向同性或各向异性，从而可在任何分辨率高效建模原子位移参数。可对任何用户定义原子进行占有率精修（分组、单原子、针对替代构象的组约束或任意混合）；替代构象中的原子根据输入 PDB 文件中的 altLoc 标识符自动识别，其占有率默认精修；有序溶剂（水）模型更新集成在精修过程中。超高分辨率数据使可视化成键效应导致的残余密度成为可能，phenix.refine 采用新颖的 Inter Atomic Scatterers 模型来充分解释这些特征。氢原子的灵活参数化允许其在任何分辨率使用，从亚原子分辨率（其参数可单独精修）到低分辨率（使用 riding 模型）。精修可使用多种目标函数，包括最大似然、带实验相位信息的最大似然以及振幅最小二乘；坐标精修可在实空间或倒空间进行（允许双空间精修）；通过提供相应 CIF 文件作为输入，新配体可容易地纳入精修（CIF 文件可用 phenix.ready_set 自动创建）。手动修正氨基酸侧链 rotamer 可能耗时，尤其对大结构；尽管模拟退火精修增大收敛半径，仍可能无法把错误建模的侧链拟合进正确密度。phenix.refine 有选项基于 rotamer 库和最优密度拟合自动选择最佳 rotamer（细节待另文发表）；此外，把实空间精修与内置 rotamer 库及可用 MolProbity 工具耦合，可自动识别并稳健修正涉及 Leu、Thr、Val、Ile 和 Arg 侧链 backward-fit 构象的常见系统性错误，该方法在 Autofix 方法中开发并测试。phenix.refine 允许多步复杂精修方案，大多数可用精修策略可相互组合并应用于模型的任何选定部分；例如一次 phenix.refine 运行可执行刚体精修、模拟退火、个体与分组 B 因子结合 TLS 精修、约束占有率精修和自动水分子拾取。其输出包括各种 map（最大似然加权、kicked、不完整性校正、异常差异以及任何用户定义系数的 map）、完整模型与数据统计，以及带格式化 REMARK 3 头、可直接用于 PDB 沉积的 PDB 文件；phenix.refine GUI 与 COOT 和 PyMol 集成，可无缝可视化分析精修模型及相关 map。phenix.refine 与其他 Phenix 组件紧密集成，使结构解析、构建和精修成为一步过程（例如在 Automr 和 Autobuild 向导中），并通过对 PDB 中所有有实验数据的模型进行自动再精修来常规测试。

配体坐标与 restraint 几何生成方面，electronic Ligand Builder and Optimisation Builder（eLBOW）是一套为新颖和已知配体可靠生成笛卡尔坐标与几何 restraints 的工具。与 Phenix 其余部分一致，eLBOW 模块用 Python 编写，数值密集部分用 C++ 编写；它是把大多数常见化学输入转换为优化三维坐标和精修用几何 restraints 的灵活平台。配体几何可用半经验 AM1 量子化学方法最小化，该方法对常与蛋白质结合的这类分子而言数值高效且化学准确。此外还开发了用于编辑几何 restraints 和配体简单几何操作的图形用户界面：Restraints Editor, Essentially Ligands（REEL）通过下拉菜单和其他交互功能提供许多常用操作，消除手动编辑 restraints 文件的繁琐；restraints 变化的效果可立即反映在分子视图中以提供用户反馈。一个利用 eLBOW 许多功能来快速简便地准备蛋白质模型以进行精修的工具称为 ReadySet!；Python 接口的灵活性体现在使用 Reduce、eLBOW 和 cctbx 工具包的若干较小部分，为模型和配体添加氢和/或氘原子，为未知配体生成金属配位文件和几何 restraints，也生成共价结合配体所需的文件。

**集成式结构解析与结论**
作者认为自动化在过去十年戏剧性地改变了大分子晶体学，既极大加速结构解析、模型构建和精修过程，也把结构解析工具带给更广泛的科学家群体；随着自动化日益全面，它将允许用户测试更多结构解析可能性、改进最终结构不确定度的估计，并解析越来越复杂和困难的结构。Phenix 环境以自动化为关键和定义性特征：Phenix 内每个工具都可无缝且几乎不费力地作为任何其他工具或流程的一部分被纳入，这意味着非常复杂的任务可由经过充分测试和表征的工具构建，工具和更高层方法可在许多不同情境中复用；完整的自动回归测试系统作为 Phenix 环境不可分割的一部分，所有这些任务和高层方法每晚测试以确保整个 Phenix 系统的完整性。

Phenix 具有完全集成的结构解析能力，既包括由 phenix.autosol 执行的实验定相（MAD、SAD、MIR 及其组合），也包括由 phenix.automr 执行的分子置换；这些自动化流程各自直接馈入 phenix.autobuild 的迭代模型构建、密度修饰和精修。phenix.autosol 旨在实现实验定相的完全自动化，同时为高级用户保留高度灵活性：从结构因子振幅和大分子序列开始，它使用 phenix.solve 缩放所有数据集，使用 phenix.xtriage 分析数据孪晶并校正任何各向异性，使用 phenix.hyss 寻找潜在重原子或异常散射原子；它用 phenix.phaser 或 phenix.solve 进行实验定相，用 phenix.resolve 进行密度修饰，并用 phenix.autobuild 中的方法进行初步模型构建。自动结构解析的一个关键步骤是识别若干可能空间群和重原子或异常散射原子亚结构中哪一个是正确的；phenix.autosol 使用基于实验电子密度图分析的贝叶斯打分算法来识别哪些亚结构导致最佳 map，评估中使用的主要 map 特征包括电子密度的偏度（非高斯直方图，正尾密度多于负尾）以及局部 rms 密度的相关性（分子所在处有大片连续高变化区域，溶剂所在处有大片连续低变化区域）。phenix.autosol 高度灵活，允许实验数据的任意组合，如 MAD+SIRAS 或多个 SAD 数据集；尽管完全自动化，用户仍可控制该流程操作的几乎所有方面，包括打分标准以及关于 phenix.autosol 对正确解包含在当前解列表中有多确定的决策。它还可结合实验 SAD 数据与分子置换信息进行定相：若有分子置换模型，phenix.autosol 将使用 phenix.phaser，基于非异常结构模型和已找到的任何异常散射原子，为异常散射原子构建对数似然梯度图，从而迭代完成异常亚结构；随后异常亚结构与模型一起用于通过 phenix.phaser 计算相位。phenix.automr 使用 phenix.phaser 执行自动的基于似然的分子置换，流程高度自动化，允许在单次运行中放置若干组分各自的若干拷贝，也可测试不同可能空间群选择；若某组分有替代模型选择，分子置换计算可依次尝试每个模型，或将其组合为统计加权集合。尽管似然目标函数的评估较慢，但旋转搜索和翻译搜索使用快速近似，使运行时间可与传统基于 Patterson 的方法竞争；似然已被证明对正确解更敏感，尤其在困难情形中；当有若干拷贝或若干组分需要放置时，似然函数利用初步部分解的能力可带来信号的关键性增强。

phenix.autobuild 是通过迭代模型构建、密度修饰和精修进行模型构建与模型改进的高度集成自动化流程。它使用 phenix.resolve 进行模型构建、模型延伸、模型组装、环拟合以及在现有模型之外构建；进一步使用 phenix.resolve 通过统计密度修饰改善电子密度图，纳入新建模型的信息以及来自实验（如 phenix.autosol）、来自 NCS 和来自电子密度图其他预期特征的信息，如平坦溶剂、二级结构特征的存在以及大分子特征性局部密度模式的存在；为减少流程中的模型偏倚，也可使用 prime-and-switch 定相。phenix.autobuild 在整个过程中使用 phenix.refine 提高所构建模型的质量。它提供两种互补的模型构建方法：在尚未构建模型或只有初步模型的情况下，phenix.autobuild 将构建新模型，把任何提供模型的主链视为潜在坐标；在已有接近最终模型的情况下，phenix.autobuild 可应用 rebuild_in_place 方法，即一次几个残基地重建多肽链，而不改变寄存器或模型总体特征。rebuild_in_place 方法通过使用不同随机种子重复重建模型，为评估原子模型中的不确定度提供了强大方法；所产生集合中每个原子坐标的变异性是该原子位置不确定度的下界。

结论部分指出，计算方法和算法的进步使 Phenix 能够自动化解析许多结构，但仍存在许多挑战；特别是开发可应用于低分辨率（差于 3.0 Å）的自动化方法仍是优先事项。在该分辨率范围内，实验数据通常太少，无法唯一确定大分子结构以进行自动化 ab initio 模型构建；因此需要依赖现有大分子结构先验知识的方法，以实现富有成效的自动化数据解读。这些方法需要为结构解析的所有阶段开发和应用，并紧密集成，以最大化从实验数据中提取的信息。
